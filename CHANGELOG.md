# Changelog

The versions follow semantic versioning: a change that breaks a command line, an option or an exit status raises the first number.

## 1.0.0, 18 November 2026

The first release. The command `cl` runs the command written after it and, when that command succeeds, puts what it printed on the clipboard: `cl realpath notes.txt` leaves the full path ready for Ctrl+V. The output still appears as usual, live, and still reaches the next program of a pipeline; the copy leaves out the final newlines and the colour and hyperlink codes, and one line on the terminal says what was copied. A command that fails copies nothing, the clipboard keeps what it had, and its exit status passes through, so that `cl cmd && next` reads as `cmd && next`. A command that prints nothing copies nothing either (status 1); cl's own failures give 125, and a command that cannot run or does not exist gives 126 or 127, as `env`, `nice` and `timeout` do. Without a command, `cl` copies what comes through a pipe.

The copy goes through wl-copy in a Wayland session, else CopyQ, else xclip or xsel in an X11 session, and through pbcopy on macOS. A clipboard program that fails or does not answer within five seconds gives way to the next one, and its child, which keeps serving the clipboard in the background, never holds the output of cl open. In a Wayland session, a copy made through CopyQ or xclip reaches the Wayland programs a few tens of milliseconds later; cl waits for it, at most a second, so that the copy is in place when cl returns. In an SSH session, or on a machine without a desktop, the terminal itself takes the copy with the OSC 52 sequence and puts it on the clipboard of the machine where its window is (Herdr, Ghostty, kitty, WezTerm and foot accept it, iTerm2 once allowed in its settings, and tmux passes it on), for a text of up to 768 KB. The option `--via` chooses the route, and `--doctor` says which way a copy would go and why, without changing anything.

A binary output, such as a picture, is copied byte for byte with its type and is kept off the terminal while it is copied, so that `cl pdftoppm -png -r 150 -f 3 -l 3 paper.pdf` puts page 3 on the clipboard as a picture. The option `-f` puts files themselves on the clipboard, for pasting into a file manager or as attachments, offered through CopyQ in the three forms that GNOME Files itself offers (a list of addresses, its own form and the plain paths); one picture goes as the picture. For emails and notes, `-c` puts the command line before its output, `-m` wraps the copy in a Markdown code block, `-Q` quotes every line for the shell and `-j` joins the lines. The option `-S` copies a secret: it is never shown, CopyQ is told to keep it out of its history, and the clipboard is cleared after 45 seconds if it still holds it. The options `-a` and `-e` copy the output of a failing command and its error stream, `-p` uses the primary selection, `-o` prints the clipboard and `--clear` empties it.

The shell additions, `eval "$(cl --shell-init bash)"`, let cl run the aliases, functions and builtins of the shell (`cl ll`, `cl history 5`), and bind Ctrl+X Ctrl+W to copying the command line being typed. The installer writes the completion for bash and zsh, which completes the command after cl as it would complete it alone.
